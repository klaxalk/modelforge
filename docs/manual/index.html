    ModelForge manual

    From drone footage to an aligned point cloud, mesh and Gaussian splat, in one web GUI.

    Overview

    ModelForge turns drone video (DJI, with its flight metadata), plain video (phone, action camera) and ROS bags into 3D models. Unlike the usual video → frames → COLMAP → nerfstudio chain, it keeps the flight metadata DJI drones record: every photo starts at its GPS / attitude pose, and the bundle adjustment refines it with self-calibrating pose priors. The results live in one local metric frame (ENU: east, north, up, in metres), so the point cloud, meshes, splat and cameras line up with each other and with the map.

    Videos / bags→Ingest (photos + priors)→Sparse (SfM)→ Sparse mesh→Gaussian splat→Search · Splat mesh · Export

    Getting started

    Start the GUI

    Everything runs in the Docker dev container (with a GPU: the CUDA image). From the repository root:

    MODELFORGE_GPU=1 scripts/dev python -m modelforge.gui.app [PROJECT] --root data --port 8080

    Then open http://localhost:8080. Without PROJECT the GUI reopens the project you had open last. --run STAGE,STAGE starts those stages at once as one job.

    Tip. After the GUI was restarted (or updated), hard-reload the page with Ctrl + Shift + R: the browser otherwise keeps the old page code.

    A first project, step by step

    1. Upload the videos (left → Videos → ＋ Upload, or copy them under data/videos/). DJI clips need no SRT file; it helps if present.
    2. Create a project (left → Projects → Create; pick its Kind: DJI, video or ROS bag).
    3. Add sources (left → Ingest): pick a clip and Add as source, or a Folder and Add all in folder. Trim each source's time range with its slider; check the plan in 3D.
    4. Press Run full pipeline (right panel). It extracts the photos, picks the photos to use (keyframes), runs SfM, the SfM mesh, the splat, the semantic features and colours the mesh. Watch the progress above the tabs.
    5. Look at the result: the quick bar's Splat, Mesh, Cams; Fly along the path.
    6. Export (left → Export): mesh and splat files to export/ or straight to your browser.
    Long runs. Large flights take hours (SfM) to days (splats of tens of thousands of photos). Put stages in the Queue, and check the memory estimate the GUI shows before heavy stages.

    Supported drones and metadata

    For DJI projects the pose priors come from the djmd metadata track inside the MP4 (one record per frame: camera, aircraft at 10 Hz, gimbal at 10 Hz). The .SRT sidecar is optional: it only gives the telemetry lead and the start time more precisely.

    Model (as the clip names it)StatusCamera heading fromNotes
    DJI NEO2 (DJI NEO2)Supported, the reference modelAircraft yaw (the gimbal has no yaw axis)Decoder reverse engineered on it; SRT lead 21.6 frames
    DJI Mavic 4 Pro (DJI Mavic4 Pro L3A)SupportedGimbal yaw (360° gimbal, true heading)Other record layout; ISO / shutter / f-number in other fields; lead by optical flow without SRT
    DJI Mavic 3 (DJIMavic3)SupportedAircraft yaw (its gimbal yaw reference shifts per flight)Latitude / longitude stored in radians (detected per clip and converted); camera record without a header. Checked against its SRT: 2–3 cm median
    Other DJI modelsTried, not verifiedGimbal yaw, unless it is over 20° off the aircraft yawRecords are found by their type, so similar layouts may work; check the priors in the Ingest 3D plan

    What is read per frame: position (latitude, longitude), altitude above take-off (barometer-fused rel_alt) and the take-off altitude, velocity (NED), aircraft and gimbal attitude, and the camera settings (ISO, exact shutter, f-number) used for the exposure correction. The aircraft and gimbal data lead the images by ~0.7 s; the lead is estimated per clip (SRT, else optical flow, else a default) and removed.

    Not supported: clips that zoom during recording (refused). Other sources: plain videos (project kind video, no metadata) and ROS 1 / ROS 2 bags (kind ROS bag, poses from TF or odometry). A project may mix drones / cameras; each camera gets its own intrinsics.

    Videos tab (the library)

    A file manager over data/videos/: folders, ＋ Upload (streaming and resumable: pick the same file again after a dropped connection or reload), clip details (length, resolution, recording time, SRT, which projects use it), add to the open project, download, rename, move, delete. Renaming or moving a clip keeps the projects using it pointing at it. ROS bags (an .mcap, a .bag or a bag folder uploaded as a zip) are listed too.

    Ingest: from video to photos

    The Ingest tab turns sources into photos with pose priors. Every edit is saved to ingest.json.

    Sources

    • A source is a video (or bag) plus a time range. The same video may appear several times (Add piece).
    • Each source has a range slider, Enabled, a telemetry lead override and an Altitude offset (auto or metres).
    • Folder narrows the clip list; Add all in folder adds every clip of that folder.
    • Sources are ordered by recording time. The first one sets the origin of the local frame.
    • Frame preview: scrub through a source; Start here / End here set its range.

    Sampling

    • Number of photos (default 300) over all sources, or a fixed spacing in metres.
    • Distance sampling (default) spaces photos by flown distance plus a credit for rotation, so turns get photos too; time sampling spaces them evenly in time. Each photo is the sharpest frame in its window.
    • Yaw source auto picks aircraft or gimbal yaw per drone model.

    Several flights

    Flights are aligned by their take-off altitudes; an implausible difference is refused with a warning (set it by hand per source). Flight alignment → Check flight alignment measures the height offsets between flights from a small set of shared photos; Run full pipeline runs it for multi-flight DJI projects.

    Extract

    Extract writes the photos and poses.json. Re-extracting needs Overwrite; the old photos and everything derived from them move to previous/.

    ROS bags

    The ROS bag folder sets the image topic (compressed or raw), camera_info, the pose source (TF world frame, odometry, or none), an optional mount rotation (Extrinsic RPY) and the point-cloud topics. LiDAR scans are merged into lidar/cloud.ply and used by dense and the splat (depth supervision).

    Mount check. A camera mounted 90° / 180° off shows as many good matches but almost no 3D points and a runaway focal length. The refine's History line then says the priors do not fit the images: try a yaw of 180 in Extrinsic RPY.

    Sparse: structure from motion

    Run SfM (all) runs features → pairs → match → refine → export → register more photos. Each stage also has its own button. The refinement is live: cameras move in the 3D view as bundle adjustment runs.

    Images used

    Extract once, then run on a subset. Selection:

    • keyframes (default): an overlap analysis of all extracted photos picks a photo whenever the overlap with the last one drops to the chosen Keyframe density (extra dense / dense / normal / sparse).
    • every N-th image, with a start offset and a time range.

    Applying a new selection moves the old results to previous/. Run full pipeline picks keyframes only the first time; later it keeps the photos in use.

    Features and matching

    • Extractor auto (default): SIFT for a single pass; ALIKED + LightGlue with the RoMa dense matcher when the flight revisits ground from other passes or other flights (different heights, directions, days). The choice is shown in History.
    • Pairs come from time neighbours plus photos looking at the same spot (from the priors, later from the terrain of an earlier model) and Pairs between passes that see the same surface in an earlier model.
    • RoMa's matches are checked against the earlier model (they must land within 10 m), because over flat ground they can "match" photos hundreds of metres apart.

    Refinement (DJI and ROS bags with poses)

    Every photo starts at its prior pose. Rounds of triangulation and bundle adjustment follow, with 6-DoF absolute and relative prior terms whose uncertainties are calibrated from the data. Along the way it estimates:

    • the camera's mounting (boresight) and the telemetry time offset;
    • a position offset per flight;
    • slow position drift within a flight, so revisits merge instead of forming offset copies;
    • outlier priors, which are rejected.
    ControlMeaning
    BA mode auto / global / chunkedGlobal if the estimated memory fits, else chunks of photos joined by a pose graph with loop closures and flight heights
    BA iterations (500)A cap per round; BA normally stops earlier when the cameras settle
    Skip this BA round / Skip refinementEnd the running BA (or all remaining rounds) with the current state, without failing
    Resume refineContinue a stopped refine from its last checkpoint
    Export: leave out isolated photosDrops photos whose ground lies in an offset copy no other pass ties in

    Heights between flights

    GPS positions of different flights agree to about a metre, but their barometric heights can be metres apart, and an unaligned flight leaves a second copy of the ground above or below the first. Heights are aligned in four places, each from shared image content (there is no ICP of point clouds):

    1. Ingest: every flight is lifted by the difference of its take-off altitude to the first flight's (refused when implausible; per source by hand: Altitude offset).
    2. Flight alignment → Check flight alignment (Ingest tab, and Run full pipeline for multi-flight DJI projects): a small SfM over photos of ground several flights saw, solving one vertical-only offset per flight; trusted offsets are applied to sources on auto.
    3. Refinement: a position offset per flight from the points seen twice (copies of the same ground), and position drift within a flight from revisits, so copies merge.
    4. Chunked refinement: flight heights in the pose graph (on by default). The pose graph lets every flight's height move as a whole (a free offset per flight) while consecutive photos keep the barometer's height differences, so a flight tied to another by matches on one stretch moves entirely, not only that stretch. The offsets go into the flights' priors, so the later bundle adjustments keep them. The log and the state line say "flight heights moved by up to … m".
    Example: berlin_all (21 Mavic 3 clips + 4 NEO2 clips over several days). Barometric heights were 5–10 m apart between days. Once the learned matching linked the flights, only the linked stretches were pulled to the other flight's height: refined camera heights jumped 6–7 m between consecutive photos, and buildings appeared stacked twice. With flight heights in the pose graph, flights DJI_0455–0458 moved down by 9.5–10.7 m as a whole, height jumps over 3 m between consecutive photos fell from 34 to 3, the passes now agree to 5 cm (median), and side views show a single roof and a single ground.

    To check a model: View → Pose graph with Edges "between passes" shows which flights are tied together; a building seen twice at different heights means a flight that is not.

    Not yet. Flights that no image links tie to the others keep their barometric height. Aligning them to a terrain model (a national LiDAR elevation model) is planned.

    Video-kind projects (and bags without poses) use Mapper incremental / global / hierarchical instead.

    Register more photos

    Adds more extracted photos to a finished model by locating each against it (the model itself stays fixed), for a denser splat without a new SfM. Choose them like Images used. It is the last step of Run SfM (all).

    Exclude photos (splat and after)

    Leave out a photo (the one selected in Inspect) or a time range, then Apply: export again. The SfM model keeps them; the splat and meshes do not see them. Undo last / Include all.

    Tie points

    When two flights or passes do not join, click the same spot in photos of each (left → Tie points, the Photo window's Tie point tab: Ctrl + click the spot, open the photos that see it, click to record), then refine again. Two or more clicks per flight / pass.

    Sparse Mesh

    A surface over the SfM points, quick to build and used as a depth prior and as starting Gaussians for the splat.

    • Run all: build → patch holes → colour.
    • Build mesh: Poisson (default; closed, then trimmed away from the points) or Delaunay (visibility-based).
    • Patch holes up to Max hole size (m) (starts at the camera spacing).
    • Colour from the photos: projects every photo onto the mesh with occlusion; live while it runs, kept if stopped.

    Splat: Gaussian splatting

    Train + export splat trains nerfstudio's splatfacto with modelforge's plugin, exports the splat and maps it to ENU. A live preview shows it growing in the 3D view every N steps.

    The training plan

    The tab works out a plan from the cameras and the GPU and shows why: image count, area, overlap, ground resolution, Gaussians needed, steps. Defaults:

    • Iterations 50,000 (per tile); 0 = automatic (20 per training photo).
    • Downsample auto: trains at ≤ 2700 px width (×2 for 4K).
    • Densification default (MCMC only when chosen: it tends to fog).
    • Image cache auto: GPU, RAM or disk, by what fits.
    • Camera pose refinement SO3xR3.

    Priors and regularisation (on by default where available)

    OptionEffect

    Tiles for large flights

    Above ~800 photos the scene is split into tiles trained one after another and merged.

    • Tile layout covisibility (default): regions of photos that see the same things, with seams on flat ground; rectangles as the alternative.
    • Photos per tile (500). Photos join every tile they show a noticeable part of.
    • Set up tiles shows the cells (View → Tile boundaries). Click a tile's ball to leave it out (grey).
    • Steps per round (10,000): every tile advances that much per round, so the whole scene appears early and improves evenly. The merged splat is updated after each round.
    • Train tiles: all, or one tile again with the current settings.

    Stop, Pause, Resume

    Stop saves a checkpoint and exports the partial splat (usable and exportable). Pause saves without the export. Resume training continues with the stored settings, step and optimiser state. For a queued training see Queue → Interrupting a long queued training.

    Difix (right panel)

    Improves the splat from viewpoints away from the flight path: Suggest target views (or your own), Refine splat with Difix, Compare before / after, Undo.

    Splat mesh and COLMAP dense

    Splat mesh

    A coloured mesh fused (TSDF) from depth rendered from the splat. Quality coarse / medium / fine sets the voxel; large scenes are fused in pieces automatically. Patch holes closes gaps up to a size.

    Dense (COLMAP MVS)

    Undistort → stereo (CUDA) → fusion → mesh (Delaunay / Poisson) → texture. Quality superfast (default, 320 px) to max (full resolution). Not part of Run full pipeline unless its "Include" box is ticked.

    Viewing and inspecting

    View tab

    • Snapshot: priors, each refinement round, refined, export.
    • Layers: points, cameras (coloured by time, source, deviation or error), thumbnails, prior cameras, prior → refined lines, trajectories, flight plan, ground grid.
    • Pose graph: lines between matched photos, coloured by inliers; "between passes" shows how flights are tied together.
    • Dense / splat: splat, mesh (sfm / splat / dense; textured where possible), dense points; Level of detail for big splats (a budget of Gaussians around the camera).
    • Sky box: sunny / cloudy / overcast, the sun where it stood during the flight.
    • Tile boundaries, Orbit, Fly, Move speed, Carry the pivot forward.

    Inspect

    Click a camera to see its photo with its observations (green), residuals (red) and unmatched keypoints (grey).

    Photo window

    Shows the photo of the camera nearest to the flight while flying; also the Tie point tab.

    Map

    Quick bar Map: a 2D map (aerial or OSM tiles, with the splat's orthophoto) with the path, the cameras, your 3D camera, heat maps (photos per area, overlap, held-out quality), tiles and pins. Click to go there, draw an area to choose sources or photos.

    Semantic search

    Left → Search: find things in the splat by words (“a car”, “gravel pile”, “a machine”).

    1. Compute semantic features (once per splat; part of Run full pipeline).
    2. Type a query and press Enter. Matches turn red; objects get yellow turning markers, listed with their size; ◀ Go ▶ flies to the camera that saw each best.
    3. Auto threshold picks the cut-off; set it by hand with the slider. Near the mesh only ignores floaters.

    Rigs: moving parts

    Left → Rig cuts an object found by Search out of the splat and lets you articulate it: joints by Ctrl + click (hinge axis, then the moving part), or proposed by UniRig / PartField, or from a template a vision model writes. A slider per joint, Animate, and export of the posed splat.

    Queue, memory and long jobs

    Queue

    Right panel → Queue: Add to queue stores a stage with the tabs' settings as they are now. Start queue runs the entries one after another. Entries of other projects run in their own process, so the view stays where it is. A browser notification tells when an entry ends. Progress shows on each entry's line.

    Memory checks

    Before heavy stages the GUI estimates the RAM needed (from this project's last run, the machine's records or a model) and asks if it may not fit; the queue waits until enough is free.

    Interrupting a long queued training to work on something else

    A splat that trains for days can be put aside and continued later without losing steps:

    1. Stop entry (not Pause queue: that only keeps the queue from starting the next entry; the running one goes on). The running tile saves a checkpoint at its current step, splat/resume.json records the run (tiled, which tile, its own settings: steps per round, plan, depth prior, camera stops), and the finished tiles plus the partial one are merged into the splat, so it can be viewed meanwhile. This takes a few minutes; wait until the entry's line says stopped before starting heavy work. The queue pauses; later entries stay pending.
    2. Open another project and work there as usual.
    3. To continue: open the project and press Splat → Resume training, or add a Resume splat entry for it to the queue. Training goes on at the same tile, step and round, with the optimiser state and schedules intact; only the trainer's restart (a minute or two) is lost.

    Watch out for two things:

    • Entries queued after the training (semantic features, splat mesh, …) must not run on the half-trained splat: move the Resume splat entry above them before Start queue, or remove them and queue them again after it.
    • Leave the project's transforms.json alone until the training is finished: Export, Register more photos, Exclude photos → Apply or a new SfM change it, and Resume then refuses (the checkpoints belong to those cameras). Work in other projects is safe.

    Stopping and restarting

    • Stop asks first, then stops whatever runs. Training saves a checkpoint and keeps the partial splat.
    • Jobs run in processes of their own: they survive a GUI restart, and the GUI reattaches to them.
    • Before restarting the GUI, check data/.modelforge_gui_busy.json: extraction runs inside the GUI process and would be lost.

    Command line

    Every stage runs without the GUI too (inside the container via scripts/dev):

    # extract photos from videos (or --plan ingest.json)
python -m modelforge.dji.extract A.MP4 [B.MP4 ...] -o PROJECT --num-images 300

# SfM and later stages
python -m modelforge.pipeline PROJECT --stages features,pairs,match,refine,export
python -m modelforge.pipeline PROJECT --stages dense --dense-quality low

# splat (wrapper running modelforge.splat in the CUDA container)
scripts/splat PROJECT [--iterations N] [--tiles auto|on|off] [--round-steps N] [--resume]

# meshes and exports
python -m modelforge.sfm_mesh PROJECT [--fill [MAX]]
python -m modelforge.splat_mesh PROJECT --quality medium
python -m modelforge.export.products PROJECT --mesh-format glb --splat-format ply

# GUI starting stages at once
python -m modelforge.gui.app PROJECT --run export,sfmmesh,splat

    Use --help on any of them for all options.

    Glossary

    ENULocal east / north / up frame in metres, centred on the first photo.
    PriorA pose from the drone's metadata, used as a soft constraint.
    SfMStructure from motion: camera poses and sparse 3D points from the photos.
    BABundle adjustment: the joint optimisation of cameras and points.
    PassA stretch of flight over some ground; a revisit is a later pass over the same ground.
    SplatA 3D Gaussian splatting model: millions of coloured, semi-transparent ellipsoids.
    TileA part of a large scene trained as its own splat, then merged.
    GSDGround sampling distance: how much ground one pixel covers.
    Held-out photosPhotos not used in training, for measuring quality (PSNR, SSIM, LPIPS).
